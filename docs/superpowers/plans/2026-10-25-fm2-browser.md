# FM2-BROWSER Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Qualify the real Chromium normal-shell FM2 path from a loaded dataset through Rust-issued direct binding, governed snapshot/compile, critique, constrained alternative lineage, non-promotion/defer, persistence, export, restore, and replay.

**Architecture:** Add a bounded production control that calls the existing `AtlasCore.compileDirectDistributionEmbodiment` entry point with a request derived only from current dataset schema metadata. Keep NIL critique/prefer and all lineage in the existing Atlas aggregate. Extend continuity export only to preserve an already-captured direct carrier; do not mint evidence or reconstruct analytical values in TypeScript.

**Tech Stack:** TypeScript, Rust/WASM runtime bridge, existing Atlas/NIL/session authorities, Vitest/jsdom for presentation-only controls, Playwright Chromium against the production Vite bundle.

**Spec:** `docs/work/FM2_RUST_DIRECT_DISTRIBUTION_BINDING_V1.md`, `docs/rfcs/0009-persisted-governed-evidence-replay.md`, `docs/rfcs/0010-moneta-semantic-snapshot-and-forma-admission.md`, and the FM2-BROWSER campaign charter.

## Global Constraints

- Rust/WASM remains the analytical authority; TypeScript may orchestrate, persist, and render only.
- The browser test must use the production normal shell and real built WASM; no prepared fixture may be injected at a Rust/direct-snapshot authority seam.
- Direct critique and constrained alternatives must remain attributable, dataset/context fenced, and non-promoting until an explicit supported promotion authority exists.
- Existing V1/V2/V3/V4 replay compatibility and legacy UI tests must remain unchanged in meaning.
- Chromium evidence is Mac/browser evidence only; it does not claim Quest, physical-device, accessibility-study, or human-comprehension qualification.

## Review Focus

- A direct compile button must refuse when no current numeric measure or committed context exists; test the visible refusal and disabled state.
- A dataset or context change after compilation must clear action eligibility and never allow a stale critique or preference to create a link.
- A constrained alternative must render as comparison/lineage with the active compilation unchanged; test that no ghost promotion or invented branch appears.
- A continuity export with a captured direct carrier must include that carrier and replay it through the real Rust producer; test missing/tampered carrier refusal through the production open/replay path.
- The visible surface must disclose whether compiled elements are conjectural and that device performance is unverified; test the exact status text rather than inferring it from DOM existence.

## High-risk pre-implementation adversarial contract

### Invariant

The normal Chromium shell may show and act on a direct compilation only after the current Atlas has acquired and runtime-validated a Rust-issued direct-distribution binding, normalized it into a runtime-issued `SemanticSnapshotV1`, and compiled it under the current committed context. A critique may add attributable ledger state and a constrained alternative link, but the active direct compilation remains unchanged until a separately authorized promotion path exists. A saved/exported state carries the exact direct carrier only when its dataset identity is current, and replay verifies that carrier through the live Rust path before any restore.

### Authority and production path

`main.ts` → `bootstrapApp` → `installInvestigationJourney` → `DesktopDirectLoopControls` → `AtlasCore.compileDirectDistributionEmbodiment` → current `AnalyticalExecutionPort` → Rust/WASM `moneta_prepare_direct_distribution_binding_v1` → `DirectDistributionBindingV1` verification → runtime-issued snapshot normalization/admission → `InvestigationAggregate` direct compiler → `NilExecutor`/`AtlasNilBindings` critique and preference routing → `NemosyneSession`/`InvestigationContinuityController` package export → `InvestigationReplayRunner` fresh Rust replay.

### Failure modes

- A UI control fabricates a snapshot, receipt, request, or active compilation from ordinary legacy analysis.
- TypeScript selects or rehashes analytical values, or packages a stale carrier after dataset, runtime, port, or context turnover.
- A stale button dispatches a critique or preference against a prior dataset/context and creates a ghost lineage link.
- A constrained alternative silently replaces the active plan, invents a branch, or is reported as device-qualified.
- Continuity export drops the direct carrier, upgrades a V2/V3/V4 claim without the required evidence, or replay trusts package bytes without fresh Rust verification.
- Visual status says “ready”, “promoted”, “verified”, or “conjectural” without the corresponding authoritative state.
- The browser test passes by using a fake prepared fixture or a mocked authority seam instead of the production bundle.

### Falsifying evidence

- A production Playwright Chromium journey loads a real sample, creates a committed investigation context through the visible journey, invokes the new direct compile control, and asserts the Rust-issued direct status, snapshot/compile identity, disclosure, critique, constrained alternative lineage, unchanged active decision, Save now/checkpoint, export carrier identities, restore, visible replay attestation, and stale/dataset refusal states.
- The browser journey inspects the downloaded package with `NemosynePackageManager` for package identity, entry presence, and the persisted direct binding identifiers, then reopens it through the visible continuity command so `InvestigationReplayRunner` performs the authoritative replay.
- Focused jsdom controls tests prove the presentation layer stays disabled without a live direct compile and clears stale eligibility after a dataset/context change; these are UI-contract evidence, not Rust analytical evidence.
- Existing real-WASM direct binding/replay suites remain the authority-seam falsifiers for altered source, request, identity, runtime, consumer, and dataset claims.

### Non-goals and dependencies

This tranche does not change Rust analytical mathematics, invent a direct evidence policy, add a new persistence store, promote alternatives, add Quest or human-study evidence, or claim device performance. It depends on the already-landed Rust binding, snapshot admission, replay carrier, NIL routing, and aggregate lineage contracts. If the normal production path cannot reach the existing Rust direct compile without a new public trust/semantic contract, stop for governance rather than adding a TypeScript fallback.
