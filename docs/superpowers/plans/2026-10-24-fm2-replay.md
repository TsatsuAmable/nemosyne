# FM2-REPLAY Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Persist and replay the Rust-issued direct empirical-distribution binding through the real export, restore, and Rust/WASM replay path without creating a TypeScript receipt authority.

**Architecture:** Add a separate, versioned direct-distribution carrier that records the Rust binding, its exact request, and an explicit use record. The package manager treats it as an optional additive entry committed by a manifest digest; replay validates the closed policy and then re-executes the existing direct-distribution operation against the reconstructed live Rust dataset before reporting the carrier verified. Existing RFC 0009 statistics receipts and legacy packages remain separate and unchanged.

**Tech Stack:** TypeScript, Vitest, Rust/WASM bridge, fflate portable package container.

**Spec:** `docs/work/FM2_RUST_DIRECT_DISTRIBUTION_BINDING_V1.md`

## Global Constraints

- Rust/WASM remains the analytical authority; TypeScript may compose, persist, transport, and compare Rust-issued bytes but may not mint a scientific receipt or recompute the distribution.
- Runtime-local handles never cross the Worker boundary; live capture uses the existing injected analytical port and current dataset/generation fence.
- `sourceJson` is hashed byte-for-byte with the existing SHA-256 helper; `receiptId` remains `direct-distribution:<sourceDigest>`.
- The direct carrier is independent of RFC 0009’s descriptive-statistics receipt bundle and must not add the direct consumer to `ConsumerPolicyRegistry.ts`.
- Old V1/V2 packages and existing V3/V4 governed statistics replay must retain their current behavior when no direct carrier is present.
- No package format bump, dependency, CI-threshold, hardware, Quest, browser, or external-service work is in scope.

## High-Risk Pre-Implementation Adversarial Contract

**Invariant:** A persisted direct-use claim is usable only when one closed V1 carrier has mutually corresponding policy/use/binding identities, exact source-byte digest and receipt identity, the package’s analytical dataset/kernel identities, and a fresh Rust/WASM replay that reproduces the exact binding from the persisted request. Missing, malformed, stale, altered, mismatched, or forged claims refuse closed-loop admission.

**Authority and production path:** Rust’s `moneta_prepare_direct_distribution_binding_v1` is the sole source/receipt producer. `AtlasCore.captureDirectDistributionBinding()` will acquire through the currently injected `AnalyticalExecutionPort` (inline or Worker), and `NemosyneSession` will only persist that returned binding plus the request. `NemosynePackageManager` owns byte-entry/digest validation; `InvestigationReplayRunner.replayPayload()` owns live dataset/kernel correspondence and re-executes the same Atlas/Rust path before accepting the carrier.

**Failure modes:** a caller supplies a TypeScript-authored or wrong-consumer claim; `sourceJson` is changed without its digest or rehashed with a forged payload; the use record names a different consumer/profile/receipt; source/use bytes are missing or stale; manifest, source, reconstructed dataset, and live kernel disagree; the direct request is altered to launder a claim; replay silently falls back to the old semantic producer or accepts an old package as governed direct evidence; Worker/runtime identity is confused with a main-thread handle.

**Falsifying evidence:** real-WASM export → package unpack → session snapshot restore → `InvestigationReplayRunner` replay succeeds for an untouched Rust binding; real-WASM replay refuses altered source with unchanged digest, altered source with a recomputed digest, missing source, missing/mismatched use, wrong consumer/profile, stale or mismatched dataset/kernel, and a forged claim; a V1/V2 package without the optional carrier still replays under its existing path; package pack/unpack rejects carrier/manifest digest disagreement.

**Non-goals/dependencies:** This does not wire the carrier into `SemanticSnapshotV1` or normal direct compilation (FM2-SNAPSHOT), does not change the RFC 0009 statistics registry, does not claim origin authentication beyond fresh Rust reproduction, and does not qualify Chromium, Quest, human comprehension, or physical hardware.

## Review Focus

- Rehashed forged `sourceJson`: replay must compare against a fresh Rust result, not trust the carrier digest alone. Test in the real-WASM replay suite.
- Missing or wrong `use`: the closed carrier parser must refuse before any direct capability is exposed. Test package payload and replay entry points.
- Old package without direct metadata: replay must not require or invent a direct carrier. Test a legacy/V2 archive.
- Dataset/kernel drift after restore: the package and live Rust result must refuse rather than downgrade to historical inspection. Test changed dataset and kernel identity.
- Worker/live identity boundary: capture must use the injected port and preserve the existing generation/fingerprint fence. Reuse the existing worker direct-binding tests and add the Atlas/session production call.
