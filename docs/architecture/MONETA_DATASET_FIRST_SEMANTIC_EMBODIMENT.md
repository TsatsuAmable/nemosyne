## 1. Decision

Adopt the dataset-first objective by **adapting the existing semantic snapshot -> RepresentationGraph -> Forma -> perceptual plan -> runtime spine**, not by creating a competing analytical authority, a universal `DATASET` renderer primitive, or a decorative dataset container.

The Dataset becomes the stable semantic **subject** and independently addressable aggregate root. Rust/WASM supplies governed semantic structures beneath that root. Moneta proposes which structures, perspectives and relationships deserve perceptual existence. Forma admits and compiles those proposals into bounded, explainable perceptual phenotypes. Runtime objects remain disposable projections.

The default overview must no longer scale its live scene with source row count. Point-per-observation presentation is reserved for explicit observation intent or bounded semantic refinement.

The design is dual-mode from the beginning:

1. **Claim-bearing mode** compiles only authoritative grounded bindings.
2. **Exploratory-abductive mode** may combine the same grounded anchor with explicitly typed imputed, hypothesized or counterfactual proposals.

Both modes use one admission/compiler boundary and one explanation/critique loop. They do not create two Monetas.

### 1.1 Why ADAPT

- **ADOPT unchanged** is rejected because current contracts do not make the Dataset a stable product-level spatial subject, do not provide a complete multi-dataset composition boundary, and do not connect the existing critique/learning contracts through a complete product loop.
- **REJECT** is rejected because the governing vision explicitly requires dataset-scale decoupling, semantic LOD, compositional Moneta, reversible explanation and human-grounded learning. QCA0 shows that the observation-first fallback is also physically unsuitable on the reference device.
- **ADAPT** preserves the correct existing authorities and landed Full-Moneta machinery while adding the missing dataset subject, working-set, comparison and product-feedback contracts.

## 2. High-risk adversarial contract

### Invariant

A dataset-first representation may reduce transfer, main-thread, scene-object and GPU cost only by compiling a bounded intent-dependent semantic working set. It must not weaken analytical authority, epistemic status, mandatory meaning, provenance, explanation, reversible detail, critique attribution or replay identity.

### Authority and production path

```text
canonical Rust dataset capability
  -> governed analytical outputs and evidence
  -> decision-independent grounded SemanticSnapshot
  -> stable Dataset subject + semantic structures
  + committed Investigation purpose / intent / perspective
  -> fixed obligations
  -> RepresentationGraph proposal
  -> one Forma admission/compiler
  -> bounded PerceptualEmbodimentPlan
  -> SpatialEmbodimentPlan backend
  -> RepresentationSurface / desktop / WebXR
```

The production entry begins at the existing dataset-load/Atlas authority and ends at the real representation surface. A helper-only demonstration is not production evidence.

### Principal failure modes

1. A dataset root is only a label, box or decorative shell around row marks.
2. A supposedly bounded overview still scans or materializes all rows in TypeScript.
3. Graph/search code invents semantic dependencies because a signature or row count makes a primitive look plausible.
4. Resource adaptation removes mandatory meaning or conjectural disclosure.
5. A model, genome, critique or archive mints evidence or changes dataset identity.
6. Two datasets collide because one graph/plan silently assumes one global fingerprint.
7. Human critique acceptance is mistaken for comprehension or an automatic learning label.
8. Search improves an internal objective while producing no human-useful or device-feasible representation.
9. A rich phenotype is treated as additional discovered meaning.
10. Browser/unit evidence is used to claim Quest cadence, comfort or human comprehension.

### Cheapest falsifying evidence

- Delete row access from the overview path; the dataset body must still compile and render.
- Hold semantic evidence constant while increasing source N; overview plan-element and rendered-object counts remain bounded.
- Remove required evidence or change epistemic purpose; admission refuses rather than inventing a substitute.
- Change only a binding, perspective, conjectural status, resource budget or dataset fingerprint; the appropriate derived identities change while unrelated analytical identity stays stable.
- Select any data-bearing perceptual property and reverse-resolve it to exact binding, primitive, semantic property, evidence/proposal, dataset, context, versions and limitations.
- Compile two independently identified datasets simultaneously; selection, explanation, refinement and replay remain unambiguous.
- Reintroduce point-per-row overview, unauthored learning labels or automatic prior updates; focused tests must fail.
- Compare the final exact-head candidate with the custody-sealed QCA0 baseline on physical Quest hardware.

### Non-goals

- No new statistical estimator or TypeScript analytical fallback.
- No universal metaphor claimed to work for every dataset or investigator.
- No claim that VR, 3D or dataset embodiment is inherently superior to simpler representations.
- No immediate world model.
- No automatic learning from clicks, dwell, adoption, successful compilation or critique acceptance.
- No requirement to implement every semantic family, modality, evolutionary operator or research question in one PR.

## 3. Problem statement and QCA evidence

Moneta's primary subject is a **dataset**, not a cloud of observations. Existing governed aggregate, distribution, density, cluster and relationship payloads already prove that Rust-owned bounded semantic embodiments are feasible. Existing semantic-detail machinery proves that exact observations can remain available without becoming the universal rendering substrate.

The remaining defect is the product-level ontology and integration path. A user can still encounter a row-addressable world whose apparent dataset representation is largely one mark per observation. The current `RepresentationGraph` vocabulary contains useful techniques but no explicit stable dataset subject. The current static Forma slice maps semantic nodes into spatial elements but does not yet establish a meaningful independently addressable dataset body. Existing System-1, search, genome, feedback and knowledge contracts are not yet joined around that subject through the real product path.

The [QCA0 record](../work/quest-compute/QCA0_BASELINE.md) is operator-accepted engineering evidence
with a custody-sealed physical Quest 3S manifest. Its governed PERF-04/PERF-05 result remains
`INVALID_RUN` because the summary emitted `deviceTarget: UNDECLARED`. The original load-duration
measurements timed dispatch and are excluded. A corrected declared-device, completion-timed physical
control run is mandatory for governed qualification; comparison with this historical run cannot
change its disposition.

The usable QCA0 observations make the cost visible on Quest 3S at 100,000 rows:

- CPU frame time was approximately 224 ms p50 and 244 ms p95;
- XR frame time was approximately 249 ms p95;
- effective cadence was approximately 4.4 frames per second;
- the scene carried approximately 2.4 million triangles and 100,000 rendered nodes;
- roughly 28 draw calls showed that draw-call reduction alone was not the governing bottleneck;
- a governor LOD scale of 0.4 did not reduce representation cardinality;
- heap/WASM capacity remained broadly flat during the five-minute run.

This is evidence of a cardinality/render correlation and an unsuitable default workload, not complete causal attribution. QCA4's marker-geometry experiments may reduce triangle cost, but substituting cheaper glyphs cannot correct the observation-first product abstraction. QCA2 still owes corrected production timing and attribution. Physical comparison remains mandatory.

The architectural performance target is therefore:

```text
source N
  -> Rust-owned evidence and analytical hierarchy
  -> bounded semantic structures
  -> intent-dependent semantic working set
  -> bounded perceptual plan
  -> small live scene projection
```

## 4. Goals and success definition

### 4.1 Product goals

1. A dataset is independently addressable, selectable, explainable and revisitable even when no observation glyph is visible.
2. The first useful view foregrounds governed dataset structure rather than row cardinality.
3. An investigator can move dataset -> structure -> subset -> observation and back without losing identity, context or provenance.
4. The same grounded dataset can support different perspectives and perceptual phenotypes without changing analytical truth.
5. Exploratory Moneta can propose missing or alternative structure while making its conjectural status impossible to erase accidentally.
6. Every representation can be inspected, critiqued, varied and compared; qualified human evidence can improve future proposals under governance.
7. Multiple datasets can coexist without identity/provenance collision and can be compared only through explicit, evidence-compatible relations.

### 4.2 Performance goals

1. Default dataset overview transfer, JavaScript traversal, plan size and rendered-object count are bounded by representation complexity rather than source N.
2. No non-observation renderer receives raw rows.
3. Resource pressure reduces optional semantic richness, background work and cold residency before mandatory meaning, interaction acknowledgement or conjectural disclosure.
4. Stronger hardware expands semantic depth, comparisons, prefetch and resident alternatives rather than merely recovering avoidable baseline inefficiency.
5. The implemented path demonstrates material physical Quest improvement against QCA0 without a scientific or interaction regression.

### 4.3 Scientific and human goals

1. Candidate names match the mathematics actually supplied.
2. Every data-bearing degree of freedom has a typed, reversible semantic binding.
3. Human recoverability is measured rather than inferred from compiler validity.
4. Critique, preference, comprehension, task outcome and discovery outcome remain distinct evidence classes.
5. A representation that is fast but misleading, unexplainable or cognitively ineffective does not succeed.

### 4.4 Programme success

FM-DSE succeeds only when all of the following are true:

- two materially different datasets produce distinct, meaningful dataset-level bodies through the production path;
- removing observation glyphs leaves each body useful and addressable;
- at least two independently governed semantic phenomena can coexist within one dataset body;
- default overview plan/render cardinality is bounded independently of source N;
- exact observation refinement is deliberate, bounded and reversible;
- grounded and exploratory purposes enforce different admissible binding sets;
- every embodied property supports structural reverse explanation;
- a confirmed human critique can instantiate an alternative without mutating the original;
- retained feedback is attributable, scoped and incapable of self-promoting a production prior;
- clean replay or safe materialized restoration preserves the experienced representation and epistemic envelope;
- physical Quest evidence demonstrates improved frame/resource behavior;
- human evidence demonstrates that the dataset body communicates at least one intended semantic distinction better than, or without material loss relative to, the selected baseline.

## 5. Terminology and four-layer model

The phrase "dataset representation primitive" is ambiguous. This design separates four layers.

| Layer | Purpose | Examples | Authority |
| --- | --- | --- | --- |
| **Dataset subject** | Stable identity and root of the represented world | dataset fingerprint, root subject, coverage/refusal state | Dataset/Rust identity projected through L0 |
| **Semantic structures** | What the evidence supports about the dataset | population, aggregate, distribution, density, cluster, topology, relationship, temporal structure, uncertainty, anomaly, missingness | Rust/WASM analytical/evidence authority |
| **Representation primitives** | How supported meanings are selected and composed | `AGGREGATION`, `DISTRIBUTION`, `DENSITY`, `CLUSTER`, `GRAPH`, `HIERARCHY`, `TEMPORAL`, `UNCERTAINTY`, `COMPARISON`, `DETAIL_EXPANSION` | Moneta / RepresentationGraph under evidence gates |
| **Perceptual/spatial primitives** | How admitted meanings become perceivable | surface, volume, field, trajectory, graph, glyph, label, colour, texture, motion, audio, interaction | Deterministic Forma compiler and qualified backends |

`POINT_IDENTITY` remains a legitimate representation primitive for explicit observation-level intent and bounded detail. A point, particle or instanced glyph may also be an internal spatial technique beneath a dataset-level semantic object, but does not make the semantic object observation-level by itself.

`DATASET` is not added to `RepresentationPrimitiveKind`. Dataset is the subject to which representation primitives apply. Making it another primitive would conflate subject and technique and invite decorative shells.

## 6. Stable Dataset subject and semantic body

### 6.1 Subject identity

The first tranche should introduce a closed `DatasetSubjectRefV1` concept:

```text
DatasetSubjectRefV1
  schemaVersion
  subjectId = H('dataset-subject-v1', { analyticalDatasetFingerprint })
  analyticalDatasetFingerprint
```

It contains no new analytical fact. It is a deterministic identity projection over the canonical dataset fingerprint. Snapshot, decision, perspective, plan, device and runtime state do not enter the subject identity.

The exact public-format placement requires the DSE0 schema/RFC review. Two implementations are plausible:

1. derive the subject reference beside `SemanticSnapshotV1` and bind it in RepresentationGraph V2; or
2. introduce a future `SemanticSnapshotV2` with a mandatory subject field while preserving V1 unchanged.

The first is the smaller migration. The second may be cleaner if other required semantic-entity/refinement fields also force a version change. **Further contract research is required before freezing the wire format.** The objective is fixed: one stable dataset subject, no new truth authority, no optional mandatory-in-practice field, and exact legacy replay.

### 6.2 Meaningful body requirement

A rendered dataset body consists of:

- one independently addressable dataset root;
- one or more evidence-bearing semantic structures, or a typed unavailable/refused state;
- explicit relations among those structures;
- explanation and refinement affordances;
- optional qualified perceptual framing that carries no hidden data meaning.

A root plus label, bounding box or shell is insufficient. Admission must reject a claimed meaningful dataset body whose only content is decorative framing or row marks renamed as a dataset.

Example:

```text
Dataset subject
  CONTAINS aggregate/population structure
  CONTAINS distribution structure
  COORDINATES_WITH relationship topology
  OVERLAY uncertainty disclosure
  DETAIL_OF bounded observation refinement
```

### 6.3 Semantic working set

The semantic working set is the subset of the dataset's supported semantic world admitted for the current context and resident in the current perceptual plan. It is controlled by explicit budgets such as:

- maximum semantic objects;
- maximum plan elements;
- maximum observation marks;
- maximum labels and interaction proxies;
- maximum resident CPU/GPU bytes;
- maximum concurrent refinement requests;
- required frame/resource envelope;
- mandatory obligations that no budget may remove.

Budgets are inputs to variant selection, not permission to reinterpret truth. When no variant preserves obligations, admission or adoption refuses/narrows scope.

## 7. Dual-mode Moneta

Dual-mode Moneta is an epistemic contract, not the System-1/System-2 distinction and not a renderer flag.

### 7.1 Independent axes

| Axis | Values | Meaning |
| --- | --- | --- |
| Epistemic purpose | `CLAIM_BEARING`, `EXPLORATORY_ABDUCTION` | What kinds of material assertion may enter the representation |
| Execution permission | `PRODUCTION`, `STUDY_ONLY`, `REFUSED` | Whether the admitted result may execute under current authorization |
| Generation regime | frozen/pinned, adaptive | Whether the proposal generator may change over time |

These axes must remain independent. An exploratory representation may be ordinary product use. A frozen exploratory treatment may be a study. `PRODUCTION` never means scientifically established.

### 7.2 Claim-bearing path

```text
Dataset
  -> Rust/WASM evidence
  -> SemanticSnapshotV1
  -> GROUNDED bindings only
  -> admitted RepresentationGraph / Forma plan
  -> reproducible dataset body
```

System-1, System-2 and search may propose representation choices but cannot invent material semantic content. Missing required evidence produces refusal, not a plausible substitute.

### 7.3 Exploratory-abductive path

```text
grounded SemanticSnapshotV1 -----------------------+
                                                    |
                   System-1 / System-2 / search     |
                                                    v
                                      ConjecturalProposalV1
                                                    |
                       grounded + conjectural Forma bindings
                                                    |
                                      exploratory dataset body
```

Conjectural properties and relations remain `IMPUTED`, `HYPOTHESIZED` or `COUNTERFACTUAL` at property/relation granularity. Their assumptions, dependencies, generator provenance, uncertainty availability, supporting evidence and contradicting evidence remain inspectable.

Promotion requires a new analytical/evidence event and new decision lineage. Geometry, human preference, model score or repeated use cannot relabel a conjecture as grounded.

### 7.4 Mode transition

Changing epistemic purpose creates a new committed Investigation context/DAG revision, revokes pending adoption from the previous context and preserves the old branch. The grounded snapshot may remain identical. Road Not Taken, Memory Palace, TechnoCore and Farcaster operate over this shared lineage rather than creating separate stores.

## 8. Representation generation and proposal sources

### 8.1 Deterministic reference composer

Every supported context needs a non-stochastic reference composition generated from exact governed semantic availability and fixed obligations. It is the baseline against which learned, synthesized and evolved candidates compete.

The current reference composer is not sufficient for dataset-first authority because signature heuristics can introduce primitives and dependency names without resolving claim-complete evidence. A row-count threshold must not imply density, and a label such as `kde_estimate` must not substitute for a governed estimator.

The replacement composer must:

- consume semantic snapshot/source identities rather than raw signature plausibility alone;
- bind every primitive to exact semantic properties and evidence/proposal references;
- produce a stable dataset root and bounded working set;
- emit typed refusal when required meaning is unavailable;
- avoid raw renderer parameters except through registered qualified recipes;
- provide deterministic identity and reverse explanation.

### 8.2 System-1

System-1 is a fast advisory proposal source. It may:

- retrieve relevant Forma cases/templates;
- rank registered representation primitives and bindings;
- propose bounded compositions and resolution variants;
- seed/prune search order;
- predict which alternatives deserve expensive evaluation;
- abstain.

It consumes compact governed features and pinned knowledge identities, never raw rows. It is not the durable store of metaphor knowledge and cannot admit a result, weaken obligations, choose evidence policy or emit unregistered arbitrary renderer parameters.

The landed FM5/FM6 machinery supplies a foundation. Dataset-first qualification still must show measurable value for dataset-body proposals over deterministic retrieval, including held-out dataset groups, abstention and target-device cost.

### 8.3 System-2 / compositional Moneta

System-2 is the explicit representation reasoning layer. It may:

- construct and compare multi-phenomenon graphs;
- reason about information preserved/lost;
- propose alternative perspectives and metaphors;
- request additional governed analysis through Atlas;
- challenge mappings and assumptions;
- synthesize bounded candidates inside the admitted grammar;
- expose alternatives through Road Not Taken.

System-2 is not a second evidence or admission authority. It need not call System-1; rules, researcher input, System-1, System-2 and search are peer proposal sources converging on one admission boundary.

### 8.4 Bounded search

Search explores a typed grammar and returns an inspectable Pareto frontier. Fitness remains vector-valued, including task relevance, information preservation, perceptual recoverability, interaction cost, resource cost, stability and explicit loss. Scientific validity is a feasibility boundary rather than a tradeable objective.

The current FM7 qualification proves bounded graph search mechanics, Pareto behavior, System-1 seeding/bypass, genome guards and replay invariance. It does not establish that the current grammar/objective functions generate human-useful dataset bodies or that loose semantic inputs are claim-complete. Dataset-first search integration therefore remains a new qualification task.

### 8.5 Evolutionary and genome search

Evolution begins only after deterministic dataset bodies, binding admission, multi-element runtime, explanation, refinement and replay are correct.

Permitted genes may include:

- selected representation primitives and composition;
- semantic hierarchy/refinement policy;
- registered perceptual bindings and metaphor templates;
- spatial allocation and admitted phenotype variants;
- interaction/detail/transition policy;
- resource and working-set policy;
- search/evaluation strategy identifiers.

Forbidden genes include:

- dataset fingerprint or subject identity;
- analytical facts or evidence receipts;
- grounded/conjectural status;
- fixed obligations;
- provenance or oracle answers;
- arbitrary unregistered analytical transformations.

The external laboratory genome remains untrusted input. Its handoff materializes an ordinary candidate graph, then subjects it to the same binding, evidence, grammar, purpose, explanation and resource gates. Lineage, ancestors, siblings and failure reasons feed Road Not Taken.

**Further research is required** to establish mutation/recombination operators, diversity preservation, compute allocation and benchmark corpora that improve semantic capability rather than combinatorial novelty. Success means non-dominated candidates that improve attributable human/task outcomes or measured resource cost without weakening meaning, not simply more graph diversity.

### 8.6 World-model research

A world model remains unscheduled. Reopen only if a named dynamic-prediction or metaphor-affordance problem cannot be solved adequately by rules, cases, explicit System-2 reasoning and bounded search. The objective would be prediction of useful interaction/representation consequences, not replacement of evidence, Forma admission or the durable knowledge base.

## 9. Forma admission, compilation and semantic resolution

One Forma entry point receives:

- exact semantic snapshot;
- stable dataset subject;
- committed context and epistemic purpose;
- fixed obligations;
- candidate RepresentationGraph with typed bindings;
- any conjectural proposals;
- pinned knowledge manifest and qualification references;
- capability/resource envelope.

It returns an immutable purpose-scoped admitted result and bounded perceptual plans, or a typed refusal.

### 9.1 Binding rules

Every data-bearing property/relation is either:

- `GROUNDED`, resolving to exact snapshot source/property/relation and evidence; or
- `CONJECTURAL`, resolving to exact proposal element/property/relation and generator lineage.

No free-form encoding string, proximity, model score or graph label may become a material semantic binding.

### 9.2 Semantic resolution

Semantic LOD changes the represented abstraction, not only mesh complexity:

```text
dataset
  -> population / distribution / topology
  -> region / substructure
  -> bounded observation subset
  -> exact datum / provenance
```

Each variant declares mandatory coverage, progressive detail, omissions, approximation, interaction affordances and resource estimates. Returning from detail restores the same dataset subject and overview lineage.

### 9.3 Performance-aware compilation

The compiler should produce backend-ready compact buffers and element descriptions from bounded semantic payloads. Renderer adapters may allocate geometry/materials, apply presentation-only transforms and build hit targets. They may not scan rows to reconstruct analytical structures.

Steady-state runtime work should use instancing, batching, culling, bounded labels, allocation reuse, multiview/foveation and GPU assistance where physical measurement justifies them. These are subordinate optimizations; no one technique is assumed to close the budget.

### 9.4 Cost model, caching and falsifiable benchmark

Let N be source observations, S the available semantic structure, K the admitted visible working set,
E its visible relations, and C the bounded candidate population. Ingestion, fingerprinting and many
exact analytical operations remain at least O(N); graph analysis may cost more. Dataset-first design
does not make those operations constant-time. The intended steady overview transfer, compilation,
hit-target storage and scene traversal are O(K + E), with explicit caps on K, E and label/channel
counts. Search cost depends on C, grammar depth and evaluations, with a wall-time/work budget.
GPU cost additionally depends on visible pixels, overdraw, material/channel complexity and geometry;
bounded element count alone cannot guarantee cadence.

The reference pipeline must acquire a bounded hierarchy cut through Rust-owned queries. Materializing
all S nodes in TypeScript and then selecting K would merely move the bottleneck. Retain canonical
analytical caches under dataset fingerprint, method/parameters and evidence/profile identities;
representation caches additionally bind snapshot, context, obligations, qualification/knowledge
manifest and generator versions. Compiled variants additionally bind the exact resource policy and
backend. A cache hit never bypasses current evidence disposition or activation checks. Purpose,
population or evidence changes invalidate affected entries; a presentation-only change may reuse the
authoritative snapshot. Bound cache residency, work queues and concurrent compilation; cancel stale
requests and account for overlap peaks during replacement. Incremental analytical algorithms require
separate Rust qualification before reuse; this design does not assume they already exist.

DSE0 must freeze a benchmark protocol before optimization:

- Compare the recorded QCA0 reference, the current low-triangle observation path, and the proposed
  dataset-body path on the same fixtures/tasks. Preserve legacy observation mode as an explicit
  control/detail choice; unsupported dataset-body compilation yields a typed unavailable/refusal
  rather than silently returning to an unbounded observation scene.
- Vary N with approximately fixed semantic information, then separately vary semantic complexity at
  fixed N. Include rare exceptions, missingness, uncertainty and a high-complexity case whose required
  meaning cannot fit; refusal is a valid outcome and must be measured.
- Measure cold ingest/analysis, first useful view, warm recomposition, steady frames, refinement,
  return, cancellation and eviction/rebuild separately. Record CPU/XR frame distributions, GPU timing
  where supported, transfer bytes, scene/interaction counts, geometry/overdraw proxies, peak residency,
  search work, and total energy/thermal behavior where available. Missing GPU timing stays unavailable.
- Use repeated, counterbalanced physical runs with pinned device model/browser/build, refresh policy,
  thermal conditions, datasets, intent and evidence. QCA0 is a historical anchor; rerun the controls
  when environment drift prevents a fair comparison. Quest 3 and Quest 3S results remain separate.
- Predeclare acceptable task-information loss, comprehension/error criteria, frame/resource budgets,
  a practically meaningful improvement margin and analysis/uncertainty protocol. DSE0 must select the
  numeric thresholds from the target refresh policy and pilot variance; this proposal does not invent
  them. A flatter warm cost curve fails the overall hypothesis if cold analysis, search, refinement,
  cognitive cost or peak memory erases the user-visible benefit.

Success requires both bounded complexity at fixed task information and measured task-equivalent
physical benefit. If either fails, revise the working-set policy or reject the performance claim.

## 10. Structural explanation, critique and human-grounded learning

All semantic bodies and metaphors must remain explainable so humans can understand, challenge and teach the mappings.

### 10.1 Reverse explanation chain

Every selectable data-bearing property must reverse-resolve:

```text
runtime object / property
  -> perceptual plan element and channel
  -> typed Forma binding
  -> RepresentationGraph primitive and relation
  -> semantic object / property
  -> grounded evidence OR conjectural proposal
  -> Dataset subject
  -> committed purpose / intent / perspective
  -> limitations, uncertainty, information loss
  -> compiler, model, template, knowledge and policy versions
```

For a compound metaphor, TechnoCore must also explain why the metaphor/composition was proposed, which semantics justify it, which forbidden implications were guarded against, which alternatives were considered and why the current candidate survived admission/selection.

Generated prose may summarize this graph but cannot replace it.

### 10.2 Typed critique

The current feedback contract is a useful minimum but remains too loose for dataset-first use: proposed bindings are strings, phenotype alternatives are narrow, attribution can default, and composition/perspective changes are not a closed grammar.

A versioned extension should support exact targets and typed proposals such as:

- `BINDING_CHANGE`;
- `PERSPECTIVE_CHANGE`;
- `COMPOSITION_CHANGE`;
- `RESOLUTION_CHANGE`;
- `INTERACTION_CHANGE`;
- `ACCESSIBILITY_CHANGE`;
- `EPISTEMIC_CHALLENGE`;
- `REQUEST_ADDITIONAL_ANALYSIS`.

Every confirmed critique binds exact plan, slice, context, dataset subject, semantic object, binding/primitive and exposure/treatment identity plus attributable author and scope. An LLM may parse a draft; the human must confirm it.

### 10.3 Alternative instantiation

```text
inspect through TechnoCore
  -> target exact property/binding/composition
  -> propose and confirm critique
  -> compile an alternative through Road Not Taken
  -> compare/use alternatives under synchronized semantic selection
  -> accept/reject/retain as an explicit branch
```

The original representation remains immutable and replayable. Accepting an alternative is not evidence that its intended meaning was understood.

### 10.4 Human evidence classes

Keep separate:

- critique/proposal;
- mapping preference;
- perceived meaning;
- task-comprehension outcome;
- misleading implication;
- accessibility/comfort issue;
- discovery outcome;
- study result.

Passive telemetry, clicks, dwell and system defaults may inform friction/resource research but cannot self-label comprehension or qualification.

### 10.5 Learning loop

```text
exact representation exposure
  -> attributable critique and meaning judgment
  -> scoped evidence/study routing
  -> curated case with contraindications and limitations
  -> explicit promotion decision
  -> durable Forma knowledge revision
  -> optional System-1/search prior update
  -> held-out evaluation and rollback
```

Earlier decisions and exposures are never rewritten when knowledge evolves. Research Mode freezes relevant knowledge/model/search identity. Learned priors may order proposals; they cannot authorize meaning or evidence.

**Further research is required** to determine which critique and meaning-judgment protocols produce reliable learning signals across domains, expertise levels and accessibility needs. The goal is improved held-out proposal coverage, comprehension/task outcomes and reduced search cost with calibrated abstention—not maximizing user agreement.

## 11. Multi-dataset composition

Current core graphs/plans are primarily bound to one dataset fingerprint. A first-class dataset design must support simultaneous comparison without weakening that invariant.

The recommended direction is independently admitted per-dataset semantic worlds/plans composed by an Investigation-owned comparison scene:

```text
Dataset A subject -> admitted plan A ----+
                                      comparison context -> coordinated scene
Dataset B subject -> admitted plan B ----+
```

Cross-dataset relations require explicit compatibility/evidence and cannot be inferred from spatial proximity. Selection, explanation, detail and replay retain the originating dataset subject.

**Further schema research is required** to decide whether cross-dataset relations belong in RepresentationGraph V2, a bounded scene-composition contract or an Investigation comparison artifact. The objective is fixed: independent fingerprints/receipts, explicit relation authority, simultaneous addressability and no merged shadow dataset.

## 12. Persistence, replay and lifecycle

Grounded claim-bearing results retain exact regeneration identity. Exploratory results also retain a materialized static capture so an evolving generator cannot erase what the investigator experienced.

Required durable state includes:

- dataset subject and snapshot references;
- context/purpose/perspective and obligations;
- selected/rejected RepresentationGraph candidates and search lineage;
- grounded/conjectural bindings;
- exact plan/variant and reverse explanations;
- generator/model/knowledge/policy identities;
- critiques, judgments, annotations and alternatives;
- static spatial organization/viewpoint where required for historical inspection;
- explicit limitations and current-disposition behavior.

Runtime objects, handles and GPU resources never become durability authorities. ACTIVE/WARM/COLD/EVICTED lifecycle may remove presentation resources while semantic state remains reconstructable. Historical inspection capability remains distinct from fresh scientific execution/adoption capability.

## 14. Research programme

These are capability gaps, not permission to invent behavior. Each item states its objective and success criterion.

### R-DSE-1 — dataset-body vocabulary and metaphor fitness

**Objective:** determine which evidence-bound compositions and metaphors help which tasks, domains and populations.

**Method direction:** known-structure corpora, conventional and deliberately misleading controls, scoped human studies, critique capture and cross-domain holdout.

**Success:** qualified mappings improve comprehension, error detection, recall or task efficiency over appropriate simpler baselines and record contraindications/abstention scope.

### R-DSE-2 — subject and multi-dataset schema

**Objective:** freeze the smallest versioned contracts that provide stable subject identity, recursive refinement and independent multi-dataset comparison without duplicating truth.

**Success:** two datasets can coexist, compare, refine, replay and explain without identity collision or optional authority fields; legacy snapshots remain exact.

### R-DSE-3 — semantic working-set policy

**Objective:** learn deterministic policies for selecting mandatory/progressive/optional semantic detail under device and attention budgets.

**Success:** bounded plans preserve obligations and human recoverability across budgets; inability to do so refuses rather than silently simplifying.

### R-DSE-4 — search and evolutionary operators

**Objective:** identify genome/operator/objective designs that produce useful, diverse, admissible dataset bodies rather than novelty or renderer parameter churn.

**Success:** a reproducible search finds non-dominated candidates with measurable held-out human/task or resource benefit over deterministic/System-1 baselines while preserving lineage and abstention.

### R-DSE-5 — critique-to-learning evidence

**Objective:** determine how confirmed critiques, meaning judgments and discovery outcomes can improve proposal priors without conflating preference, comprehension and truth.

**Success:** curated attributable feedback improves held-out proposal coverage/regret or comprehension outcomes, passes dataset/investigator-disjoint evaluation and supports rollback.

### R-DSE-6 — dual-mode perceptual disclosure

**Objective:** find perceptual/interaction techniques that keep grounded and conjectural content distinguishable without making exploratory work unusable.

**Success:** users correctly identify epistemic status and assumptions under representative tasks; disclosure survives resolution/resource adaptation and accessibility conditions.

### R-DSE-7 — Quest semantic-efficiency frontier

**Objective:** characterize how source N, semantic complexity, visible working set, refinement, search breadth and hardware budget interact on Quest 3S.

**Success:** controlled physical runs show stable bounded cardinality and material cadence/resource improvement against QCA0, with no semantic/interaction regression and honest attribution.

### R-DSE-8 — adaptive-depth/shared model hypothesis

**Objective:** compare specialist System-1 plus explicit System-2 search with a bounded adaptive-depth recurrent/shared-expert proposal substrate.

**Success:** the shared model materially improves proposal quality/cost or exploratory reasoning without increasing governance, replay, abstention or target-device risk beyond its benefit. Otherwise retain specialists.

### DSE1 — stable subject and grounded bounded overview

- derive the stable Dataset subject from authoritative fingerprint;

- supply a bounded deterministic composer whose every binding resolves supported semantics and evidence before admission;

### DSE2 — semantic refinement and resource variants

- dataset -> structure -> subset -> observation -> datum traversal and return;
- admitted semantic-resolution variants under existing resource broker/lifecycle;
- refusal when budgets cannot preserve obligations;
- exact selection/context identity across refine/collapse/evict/reconstruct.

**Exit:** semantic continuity and disclosure survive materially different budgets and lifecycle states.

### DSE3 — dual-mode product loop

- bind grounded and conjectural paths to the same Dataset subject;
- finish visible epistemic disclosure and mode transition;
- extend typed critique and meaning judgment targeting;

### DSE4 — multi-dataset comparison

- compose two independently admitted dataset worlds;
- explicit cross-dataset comparison authority and synchronized selection;
- independent refinement, eviction, explanation and replay.

**Exit:** two materially different datasets meet the minimum proof in the dataset-level critique without fingerprint/provenance collision.

### DSE5 — proposal/search/evolution integration

- generalize the DSE1 evidence-bound deterministic composer for the broader supported grammar, replacing remaining heuristic paths before their use;

**Exit:** at least one non-reference proposal demonstrates held-out benefit without bypass; deterministic fallback and ABSTAIN remain usable.

### DSE6 — physical and human qualification

- corrected governed physical control capture and exact-head Quest comparisons, retaining QCA0 as historical engineering evidence and controlled renderer variants;
- corrected main-thread/Worker/GPU attribution;
- long-session bounded-resource evidence;
- known-structure and investigator semantic-recovery studies;
- accessibility and dual-mode disclosure evaluation;
- STOP/CONTINUE/REVISE decision.

**Exit:** physical performance and scoped human value are demonstrated at the applicable evidence tiers. Otherwise retain the truthful deterministic subset and revise/stop unsupported claims.
