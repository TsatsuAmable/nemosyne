Roadmap to a qualified research preview

The Rust/WASM authority migration is complete. Nemosyne is now in pre-P1 hardening and qualification; feature count does not substitute for evidence that the full investigation works safely on its target hardware.

Next implementation order

  1. Qualify the device boundary. Run the instrumented 10M-row and interaction protocols on physical Meta Quest 3S hardware.
  2. Close lifecycle risk. Split oversized coordinators along authority and ownership seams; prove disposal and recreation.
  3. Prove the user journey. Exercise visible controls from data load through Moneta/NIL, investigation, export, and replay in a real browser.
  4. Harden hostile boundaries. Fuzz the Rust ABI and package inputs; inject kernel, signalling, and reconnection faults.
  5. Measure spatial performance. Select one production query accelerator from device benchmarks and remove redundant paths.

Private preview gate

P1 can reopen only after blocker and high-severity audit findings have governed dispositions, the full CI gate remains green, and target-device evidence is reviewed. Learned ranking and future adaptive representation remain opt-in and must not bypass evidence policy.

Evidence vocabulary

  • Built: a component and tests exist.
  • Wired: production instantiates the component.
  • Qualified: the declared environment and protocol pass.
  • Validated: research evidence supports the intended human outcome.
