# Analysis plan

Status: Draft; freeze before data collection begins.

## Purpose
This document defines the planned comparisons before collection begins so that post-hoc selection is not possible.

## Primary outcome
The primary outcome should be the task accuracy measure that best reflects the study objective. A recommended default is accuracy on the fraud-detection task as scored against the study ground truth.

## Secondary outcomes
- completion time
- confidence rating
- workload score
- navigation cost derived from telemetry
- recall if a delayed-recall condition is included

## Planned comparisons
At minimum:
- 2D vs. VR

These comparisons are pre-registered and should not be changed after the data are seen.

## Exclusion rules
Exclusions should be defined before data collection.

Standard rules include:
- incomplete trials
- trials with researcher intervention outside the declared policy
- technical failures that are not part of the study manipulation itself
- ineligible participants

All exclusions should be documented and reported, not silently applied.

## Missing-data treatment
Missing trial data must be handled consistently. The chosen rule should be declared before collection begins. At minimum, the package must specify whether partial trials are dropped for the primary outcome, retained for completion-rate reporting, or otherwise handled.

## Planned qualitative coding
If observer notes or debrief data are used, define the coding scheme before collection begins.

Recommended categories include:
- confusion
- hesitation
- discovery
- navigation difficulty
- gesture or control difficulty
- verbal query
- other open-code categories as needed

## Change-control policy
No planned comparison may be edited after data collection starts unless a formal protocol deviation is recorded. If an issue is discovered mid-study, document the reason and the change rather than silently altering the analysis plan.
